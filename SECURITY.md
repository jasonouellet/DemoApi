# Security Policy

## Supported Versions

Security fixes are provided for the active development line.

| Version | Supported          |
| ------- | ------------------ |
| main (latest) | :white_check_mark: |
| older commits/tags | :x: |

If you need long-term support for a specific release line, please open a discussion first.

## Reporting a Vulnerability

Please do not open public issues for security vulnerabilities.

Use one of these private channels instead:

1. GitHub Security Advisories (preferred): use the repository Security tab and create a private vulnerability report.
2. If private reporting is unavailable, contact the maintainer directly through repository owner contact methods.

When submitting a report, include:

1. A clear description of the issue and impacted component.
2. Reproduction steps or proof of concept.
3. Potential impact and attack scenario.
4. Suggested remediation if available.

Response expectations:

1. Initial acknowledgment within 3 business days.
2. Triage and severity assessment within 7 business days.
3. A fix timeline shared after triage based on severity and complexity.

After a fix is available, we may publish a security advisory with coordinated disclosure details and upgrade guidance.
